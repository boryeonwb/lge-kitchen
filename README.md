# 광고주 공유용 운영·정산 대시보드 (lge-adv-dashboard)

LG전자 냉장고(HS NPI) 광고주에게 공유하는 화면입니다. 탭은 둘입니다.

| 탭 | 내용 |
|---|---|
| **정산** | 인보이스에서 읽은 금액(통화·인보이스 최종금액·DST안분·무효반영·광고비net)과, 그 라인이 세금계산서로 나가는 금액(적용환율·매체비KRW·와이즈버즈 수수료KRW·최종 발행 금액·발행월·처리주체). **키친만** 다룹니다 |
| **운영** | 품의예산(USD/KRW)·품의환율 대비 잔여금과, 남은 기간에 태울 세팅 예산(총예산·일예산·세팅통화), 그리고 월별 소진(세팅통화·KRW) |

**이 저장소에는 프런트엔드만 있습니다.** 계산도 데이터도 없습니다.

---

## 숫자는 어디서 오는가

```
lge-billing-dashboard (내부 정산 대시보드)
  backend/calc.py · ops.py        ← 인보이스 파싱 결과 · 환율 · 품의예산 시트
  backend/adv.py                  ← 광고주에게 보여줄 열만 고르는 화이트리스트
      GET /api/adv/settlement
      GET /api/adv/ops
            │
            │  (nginx 프록시 /api → 그 백엔드)
            ▼
lge-adv-dashboard (이 앱)          ← 표시만 한다. 읽기 전용
```

**데이터를 복제하지 않는 이유가 있습니다.** 적용환율(HSAD 내부환율), 매체비·수수료 수기수정,
세금계산서 발행월, 품의환율, 월별 원통화 소진액은 **사람이 내부 대시보드 UI 에서 입력한 값**이고
그쪽 PVC 에만 존재합니다. 여기서 따로 들고 있으면 광고주 화면이 내부 화면과 조용히 어긋납니다.
그래서 백엔드를 공유합니다 — 내부에서 값을 고치면 이 화면도 같이 바뀝니다.

**보이지 않는 것:** 청구율, 내부 최종금액 KRW, 차액(세금계산서−내부), 수익/손실, 계정ID,
비고·메모·수정 이력, 인보이스 원본 PDF, 내부 운영 경고, 미디어믹스 시트 링크.
거르는 위치는 이 앱이 아니라 **백엔드**입니다(`backend/adv.py`) — 브라우저까지 오지 않습니다.

> **인증이 없습니다.** 주소를 아는 사람은 볼 수 있습니다(요청 사항). 내부 대시보드의 운영 화면은
> 비밀번호로 막혀 있지만 `/api/adv/ops` 는 그 일부를 열어 줍니다. 막아야 하면 백엔드의
> `_ops_guard` 와 같은 방식으로 별도 비밀번호를 붙이면 됩니다 — 쓰기 경로는 원래 없습니다.

## 실행

```bash
npm install
npm run dev            # → http://127.0.0.1:3100
```

`/api` 는 `http://127.0.0.1:8000`(정산 백엔드)으로 프록시됩니다. 다른 포트로 띄웠으면:

```bash
API_TARGET=http://127.0.0.1:8123 npm run dev
```

백엔드 쪽은 `lge-billing-dashboard/backend` 에서 띄웁니다(경로 설정은 그쪽 README 참고):

```bash
uvicorn main:app --port 8000
```

`npm run typecheck` · `npm run build` 로 검사·빌드합니다.

## 로컬 배포 (지금 바로 쓸 수 있는 방법)

클러스터에 올리기 전에 **사내망 로컬 사이트**로 돌릴 수 있다. 배포에서 nginx 가 하는
일(정적 서빙 + `/api` 프록시)을 `serve_local.py` 가 대신한다 — Docker 가 필요 없다.

```bash
npm run build            # dist/ 만들기 (한 번만, 코드를 고치면 다시)
python serve_local.py    # 0.0.0.0:3100 · /api → 127.0.0.1:8000
```

정산 백엔드도 같이 띄워야 한다 (이 앱은 숫자를 직접 가지지 않는다):

```bat
cd <lge-billing-dashboard>\backend
set LGE_WORK=C:\lgwork
set LGE_STATE=C:\lgwork\adv_state
set LGE_PROJECT=C:\lgwork
python -m uvicorn main:app --host 0.0.0.0 --port 8000
```

둘을 한 번에 띄우는 **`로컬_실행.bat`** 이 같은 폴더에 있다 (경로는 파일 상단에서 수정).

| 여는 주소 | 누가 |
|---|---|
| `http://localhost:3100` | 이 PC |
| `http://<이 PC IP>:3100` | **같은 망의 다른 PC** — `serve_local.py` 가 0.0.0.0 에 붙어 사내 공유가 된다 |

알아둘 점

- `npm run dev` 는 **localhost 에만** 붙어 혼자만 볼 수 있다. 공유하려면 `serve_local.py` 를 쓴다.
- 프록시를 두는 이유는 **CORS** 다. 브라우저가 백엔드를 직접 부르면 출처가 달라 막히는데,
  같은 출처로 들어와 서버가 넘겨 주면 백엔드를 그대로 쓸 수 있다 (배포의 nginx 와 같은 구조).
- 백엔드가 안 떠 있으면 화면이 조용히 비는 대신 상단에 **사유가 뜬다** — 프록시가 502 응답에
  연결 오류를 실어 준다.
- **내부 상태 파일이 필요하다.** 사람이 내부 대시보드에서 넣은 값(HSAD 내부환율 · 매체비/수수료
  수기수정 · 세금계산서 발행월 · 품의환율 · 월별 원통화)은 `LGE_STATE` 폴더에만 있다. 로컬에서
  운영과 같은 숫자를 보려면 그 폴더를 운영분으로 채워야 한다:

  ```bash
  curl -s https://lge-billing-dashboard.wisebirds.ai/api/data -o prod.json
  # prod.json 의 issueMonths  → <LGE_STATE>/issue_months.json
  # 행별 taxOv               → <LGE_STATE>/tax_overrides.json
  ```

  이 값이 없으면 **발행월이 전부 '미발행'으로, 수기수정 이력이 하나도 없는 상태**로 뜬다.
  숫자 자체는 나오기 때문에 그냥 넘어가기 쉬운 함정이다.

## 배포

`argocd-app-chart` 가 `image.repository` / `nameOverride` / ingress
(`lge-adv-dashboard.wisebirds.ai`)를 자동 주입합니다. `deploy/values.yaml` 은 **frontend
컴포넌트만** 정의합니다 — backend 도 PVC 도 없습니다.

| 환경변수 | 기본값 | 내용 |
|---|---|---|
| `API_UPSTREAM` | `http://lge-billing-dashboard-backend:8000` | `/api` 를 넘길 정산 백엔드 주소. 컨테이너 기동 시 `envsubst` 로 `templates/default.conf.template` 에 채워집니다 |

서비스 이름이 다르면 `deploy/values.yaml` 의 `API_UPSTREAM` 만 고칩니다. 다른 네임스페이스면
`<svc>.<namespace>.svc.cluster.local:8000`, 클러스터 밖이면
`https://lge-billing-dashboard.wisebirds.ai` 도 됩니다. nginx 는 변수 없는 `proxy_pass` 의
호스트를 **기동 시 한 번** 해석하므로, 주소가 틀리면 조용히 500 을 내는 대신 기동에 실패합니다.

## 디자인 — Popcorn (warm editorial monochrome)

크림색 종이(`#f7f7f7`) 위의 따뜻한 그래파이트(`#393737`). 색을 거의 쓰지 않고 서체 대비·자간·
부드러운 그림자 하나(`rgba(0,0,0,.05) 0 4px 20px`)로 위계를 만든다. 인터랙티브한 표면은
전부 pill(100px), 판은 12px 라운드.

토큰은 `src/styles.css` 의 `@theme` 한 군데에 모여 있다. 서체는 `index.html` 이 구글 폰트로
불러온다 — 막힌 망에서는 스택의 시스템 서체로 조용히 내려간다.

| 가이드 | 여기서 쓴 것 | 이유 |
|---|---|---|
| Untitled Serif (디스플레이) | **Source Serif 4** + 한글 **Noto Serif KR** | 유료 커스텀 서체라 가이드가 지정한 대체서체. 제목이 대부분 한글이라 한글 세리프를 짝지어 둔다 — 없으면 한글만 시스템 명조로 떨어져 한 줄의 인상이 갈린다 |
| Messina Sans (기능) | **Inter** + 시스템 고딕 | 같은 이유 |

**가이드에서 일부러 다르게 해석한 세 가지** — 원본은 마케팅 랜딩이고 이건 열이 서른
개가 넘는 표라, 그대로 옮기면 쓸 수 없는 화면이 된다.

1. **디스플레이 세리프는 제목·KPI 숫자에만.** 페이지 제목 22px, 섹션 제목 22px,
   KPI 숫자 40px. 표 안 글자는 사스 기능 사이즈(11·13·14px)로 내렸다 — 본문 16px 을
   표에 쓰면 한 화면에 여덟 줄밖에 못 담아 대조가 안 된다. 가이드의 84px 는 쓰지 않는다.
2. **수익/손실·초과 같은 신호를 채도 있는 글자색 대신 연한 틴트 pill 로** 냈다.
   시스템이 채도 있는 텍스트를 금지하는데, 금액 화면에서 음수·초과를 구분 없이 두면
   눈에 안 들어온다. 스펙트럼 워시의 blush(`#f7dbe5`)·amber(`#fef1d8`)·mist(`#e9eff6`)를
   배경으로만 쓴다. 숫자 열에서는 배지 오른쪽 여백만큼 당겨 자릿수가 안 어긋나게 한다.
3. **페이지 폭을 1200px 로 안 묶었다**(1720px). 운영 탭은 고정 13열 + 월별 2열이라
   1200px 에 넣으면 고정열만 보이고 가로 스크롤로만 읽게 된다.

## 이 앱이 쓰는 값 — 잔여금 이관 배분 하나

그 밖의 모든 값은 읽기만 한다. 이관만 예외인 이유는 **어떤 원장에도 없는 사람의 판단**
이기 때문이다 — 끝난 차수의 남은 돈을 어느 라인에 얼마나 넘길지는 담당자가 정한다.
화면 안에만 두면 새로고침에 사라지고, 같이 보는 사람마다 다른 화면을 보게 된다.

저장하는 건 금액이 아니라 **잔여액 대비 비율**이다. 잔여액은 환율이 갱신되면 같이
움직여서, 금액을 굳혀 두면 그때부터 배분 합이 잔여액과 어긋난다.

    GET  /api/adv/carry        저장된 배분
    POST /api/adv/carry        {"id": 출발행, "share": {도착행: 비율}}  · share 가 비면 해제
    POST /api/adv/carry        {"clear": true}                        · 전부 해제

저장 위치는 백엔드 STATE 의 `carry_plans.json` 이다(PVC). 운영 탭 페이로드에 같이 실려
오므로 화면이 두 번 그려지지 않는다.

**인증이 없는 화면이라 링크를 아는 사람은 누구나 고칠 수 있다.** 같은 화면을 같이 보자는
것이 목적이라 그대로 두되, 저장량은 서버가 막는다(출발 500행·도착 50행, 비율 0~1).
실제 품의·매체 세팅을 바꾸는 것은 아니고 이 화면의 계산 기준일 뿐이다.

## 새 매체 소진액 굳히기 (통합 raw 스냅샷)

인보이스가 아직 없는 달은 소진액을 알 수 없어 운영 탭이 **계획값**(잔여액을 남은 일수로
나눈 추정)으로 채운다. 그건 실적이 아니다. 성과 리포팅 파이프라인(`lge-kitchen-report`)이
만든 통합 raw 를 받아 그 달을 실적으로 덮는데, **상시 조회하지 않고 파일로 굳힌다** —
원본 시트는 그때그때 확인용으로 공유받는 것이고 계속 열어 둘 시트가 아니다.

시트를 새로 받았다면(매체·기간을 바꿔 다시 만든 것) 백엔드를 띄운 채로:

```bash
cd backend            # lge-billing-dashboard 쪽
python raw_sheet.py <스프레드시트ID> <gid>
```

`raw_snapshots/<달>_<매체>.json` 이 매체별로 생긴다. 백엔드가 다음 요청에서 바로 읽으므로
재시작도 캐시 비우기도 필요 없다.

**매체별 파일인 이유:** 같은 시트가 한 번은 Criteo, 다음엔 DV360 으로 갈아끼워져 온다.
한 파일에 섞으면 새로 받은 매체가 예전 매체의 달을 통째로 지운다. 덮어쓰기 단위는
**매체 × 달**이다.

굳힌 뒤 콘솔 출력을 꼭 본다. 조용히 빠지는 걸 막으려고 두 가지를 알린다.

- `! 미매칭 <솔루션>|<국가>` — 운영 화면에 없는 솔루션·국가. 그만큼 소진액이 덜 잡힌다.
  차수로 갈린 국가(`Tunisia_1st`/`2nd`)는 raw 에 `Tunisia` 로 오는데, 인보이스와 같은
  규칙으로 그 달이 기간에 걸치는 차수에 자동으로 보낸다(둘 이상이면 품의 비례).
- `운영 화면에 없는 매체명` — raw 와 정산의 표기가 다른 경우다(`pintrest` → `pinterest`,
  `meta` → `fb-ins`, `teads` → `tead`). `raw_sheet.MED_ALIAS` 에 추가한다. 맞추지 않으면
  그 매체는 **아무 행에도 안 붙고**, 화면에는 계획값이 그대로 남아 아무 일 없어 보인다.

주의할 것

- 금액은 `Cost (Net-Total)` 을 쓴다. `Cost (net-net)` 은 DST 차감분이라 정산의 DST 안분과
  이중 차감된다.
- 통화는 USD 다. 세팅 통화가 EUR·GBP 인 나라는 USD→KRW→세팅통화로 되돌린다.
- **진행 중인 달은 스냅샷이 계속 뒤처진다.** 굳힌 날까지만 실적이고 그 뒤로는 안 늘어난다.
  그 달이 끝나면 다시 굳혀야 한다.
- 조회일 당일은 뺀다 — 리포트가 아직 다 차지 않아 그날치는 들쭉날쭉하다.

## 화면에서 알아둘 것

**정산 탭**

- `광고비net` = 집행 + DST안분 + 무효반영. **인보이스 통화 그대로**라 소계·합계는 통화별로 나눠 냅니다.
- `인보이스 최종금액`은 그 라인이 속한 **인보이스(계정)의 발행 총액**이라 집계행마다 되풀이됩니다 →
  합계를 내지 않습니다(내면 중복 계상).
- `최종 세금계산서 발행 금액` = 매체비KRW + 수수료KRW. 단 **처리주체가 HSAD(광고주계정)** 인 행은
  매체비를 광고주가 매체에 직접 지불하므로 **수수료만** 발행합니다 → 그 행의 매체비 칸은 흐리게 내려둡니다.
- `적용환율`은 세금계산서 환산 환율입니다. Criteo 는 HSAD 내부환율, 그 외 매체는 정산 적용환율과 같습니다.

- 내부 정산 대시보드에서 한 **세금계산서 수기 수정은 그대로 따라옵니다.** 금액은 서버가 이미
  반영해 내려주므로 여기서는 **누가 왜 고쳤는지**를 같이 보여 줍니다 — 고쳤진 칸에 ✎ 와 노란
  배경이 붙고, 마우스를 올리면 수정자·사유·시각과 이전 이력이 다 보입니다. 이쪽이 **공유되는 기록**입니다.

- 상단 요약 카드는 **정확한 원 단위 금액**을 큰 글씨로 내고, 억원 환산은 아래에 작게 둡니다.

**운영 탭**

- 월별 소진 KRW 는 한 달에 **하나만** 쓰고, 어느 값을 쓸지는 서버가 정합니다:
  **확정**(인보이스, 굵게) > **수기**(매체 리포트 기준, 틴트 배지) > *계획*(잔여액을 남은 일수에 일할
  배분 · 기울임, **실적이 아님**). 세팅통화 칸도 **같은 출처**로 짝을 맞춰 두 칸이 어긋나지 않습니다.
- `잔여액` = 품의예산(KRW) − 확정 − 수기 = **아직 어느 달에도 배분되지 않은 돈**입니다.
  '앞으로 쓸 수 있는 돈'이 아니라 계획이 덜 짜인 금액이라, 0 에 가까울수록 품의에 맞게 계획된 상태입니다.
  종료됐는데 남아 있으면 그만큼 못 쓰고 끝난 것이라 ⚠ 로 표시합니다.
- `세팅 일예산`은 **오늘 매체에 넣을 값**, `세팅 총예산`은 **캠페인 총예산 칸에 넣을 값**(이미 태운
  몫 포함)입니다. 원통화 열은 행마다 통화가 달라 합계를 내지 않습니다.
- 기간·잔여일은 **각 국가 현지 날짜** 기준입니다.
- 월 열은 값이 하나라도 있는 달만 냅니다. **전체 행 기준**으로 정하므로 드롭다운을 바꿔도 월 위치는
  고정됩니다.
- 운영 탭은 **드롭다운과 표만** 둡니다. 상단 KPI 카드·제목 블록은 두지 않습니다 — 한 화면에
  표를 최대한 담는 게 이 화면의 일입니다. 요약 수치는 툴바 오른쪽에 한 줄로 남겨 둡니다.

### 잔여금 이관 (툴바의 [잔여금 이관] 버튼)

끝난 Phase 에 남은 돈을 **같은 솔루션·같은 국가의 다음 Phase** 로 넘겨, 그 Phase 의
세팅 총예산·일예산을 다시 계산해 보여 줍니다. 구현은 `src/lib/carry.ts` 입니다.

> **화면 안에서만 계산합니다.** 서버에 쓰지 않고, 끄면 원래 숫자로 돌아갑니다.
> 실제 품의나 매체 세팅을 바꾸는 게 아니라 "이렇게 넘기면 세팅 금액이 얼마가 되는가" 를
> 보는 계산입니다.

| 규칙 | 내용 |
|---|---|
| 묶는 단위 | 솔루션 × 국가. Phase 는 그 안에서 **종료일 순**으로 줄을 선다 — '이전 차수' 는 결국 먼저 끝나는 차수이고, 이름(`Phase1-1` 등)으로 줄 세우면 표기에 끌려다닌다 |
| 끝났다의 기준 | 그 Phase 의 **모든 행**이 종료(잔여일 0). 기간을 모르는 행이 섞이면 끝난 것으로 보지 않습니다 |
| 흐름 | 다음 한 칸으로. 그 Phase 도 끝났으면 **누적해** 다음으로 흘러가고, 아직 안 끝난 Phase 를 만나면 거기서 멈춥니다 |
| 받는 행 | 그 Phase 안에 **진행 중인 행이 있으면 그 행들에만** 품의예산 비례로 담습니다. 같은 차수라도 매체마다 종료일이 다를 수 있는데, 이미 끝난 매체에 담아 봐야 태울 수 없습니다 |
| 세팅 금액 | **끝난 차수에는 세팅 금액을 늘리지 않습니다** — 태울 날이 없습니다. 서버(ops.py)도 종료 행에서는 `setLife = natDone` 으로 둡니다. 그래서 종료 행은 잔여액과 이관 표시만 바뀝니다 |
| 마지막 Phase | 끝나고 남은 돈은 갈 곳이 없어 그대로 남습니다(⚠ 유지) |
| Phase 공란 | 어느 차수인지 알 수 없으므로 체인에서 빼고 원래대로 둡니다 |
| 계산 범위 | 드롭다운과 무관하게 **전체 행**으로 계산합니다. 필터로 앞 차수를 가린 상태에서 계산하면 화면에서 사라졌다는 이유로 이관액이 달라집니다 |

표시 — `잔여금 이관(KRW)` 열이 잔여액 오른쪽에 붙고, 받은 것(`↙ +`)과 넘긴 것(`↗ −`)을
따로 냅니다. 가운데 차수는 둘 다 생기므로 두 줄로 보입니다 — 하나만 내면 "받았는데
잔여액이 왜 0 이지" 로 읽힐니다. 세팅 금액이 **실제로 늘어난** 행만 틴트로 강조합니다.
